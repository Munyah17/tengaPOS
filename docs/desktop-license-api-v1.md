# TengaPOS Desktop — Licensing & Update API Contract v1

**Status:** DRAFT — pending sign-off before implementation.
**Version:** `v1` (path-versioned; breaking changes ship as `v2`, never in-place)
**Owner:** Platform (Super Admin operates releases; tenant admins operate their own terminals)

This document is the binding contract between:

- **Server** — Supabase Edge Function `desktop-license` (`/functions/v1/desktop-license/v1/*`) + Postgres tables
- **Desktop client** — built in Microsoft Visual Studio from this repo's codebase, plus an offline layer (`C:\Users\MeXa\Desktop\TengaPOS Desktop Real`); runs **fully offline** using local machine storage + local database after activation
- **Web app** — this repo; tenant admin terminal management + Super Admin release management + public **.exe download** of the desktop installer

The online app distributes the installer itself: `GET /v1/download` returns a signed, time-limited URL to the current stable installer artifact. The installer alone grants nothing — the machine is inert until activated with a product code bound to that single device.

Two hard boundaries, stated up front:

1. **The server signing private key never leaves server-side storage.** It lives in Supabase Vault (`desktop_license_signing_key`). Clients ship only the embedded public key.
2. **Revocation cannot reach a permanently disconnected computer.** A device that never checks in again keeps working until its lease `expires_at` passes — and can keep working in degraded mode until `grace_until` if we choose to let it. After `grace_until` the desktop app itself must refuse to open for business. This is a floor the client enforces, not something the server can force.

## 1. Security model

| Key | Generated by | Stored | Purpose |
|---|---|---|---|
| Server signing keypair (Ed25519) | Platform, once | Private: Supabase Vault. Public: compiled into desktop builds + served in `/v1/meta` | Sign leases + update manifests + artifact digests |
| Device keypair (Ed25519) | Desktop, per installation, at first launch | Private: OS-backed storage (Windows DPAPI / macOS Keychain / Linux Secret Service via `keytar`/`safeStorage`); fallback: file with 0600 perms under user-data dir | Prove device identity on check-in; activation binds the public key |
| Activation code | Tenant admin via web app | Hash only (SHA-256) in DB; raw code shown once | One-time, short-lived bootstrap credential |

- All signatures are **Ed25519** over canonical JSON (UTF-8, keys sorted, no insignificant whitespace). The canonical form is part of the contract — a signature is valid only over the canonical bytes.
- Device-authenticated endpoints require header `X-Device-Id` + `X-Device-Signature` (base64 Ed25519 over `METHOD\nPATH\nTIMESTAMP\nSHA256(BODY)`), `X-Device-Timestamp` within ±5 min of server time. Nonces are not required per-request; timestamp skew window + unique `checkin_id` dedupe covers replay on check-in.
- HTTPS only. Certificate pinning is out of scope for v1 (documented risk).
- Clock-rollback defense: server embeds `server_time` in every response; the desktop stores `max_server_time_seen` and refuses to trust a lease `issued_at` earlier than it.

## 2. API endpoints

### 2.1 Activation codes (tenant admin, Supabase JWT)

**`POST /v1/activation-codes`**
Request: `{ "device_label": "Front Counter PC" }`
Response `201`: `{ "code": "TGA-9K4F-7Q2P", "code_id": "uuid", "expires_at": "ISO" }`

- Format: `TGA-XXXX-XXXX`, Crockford base32 (no 0/O/I/L), ~40 bits entropy.
- `expires_at` = `now + 15 minutes`. **Single-use, atomic**: consumed inside the activation transaction; a second use returns `410 Gone`.
- Stored hashed. Raw code is returned once and never retrievable again.

**`DELETE /v1/activation-codes/{code_id}`** — revoke an unused code. `204` or `409` if already consumed.

**`GET /v1/activation-codes`** — list tenant's codes (id, label, status `pending|consumed|expired|revoked`, created/expiry, consumed_by_device_id).

### 2.2 Device activation (desktop, unauthenticated)

**`POST /v1/activate`**
Request:
```json
{
  "code": "TGA-9K4F-7Q2P",
  "device_name": "Front Counter PC",
  "device_public_key": "base64-ed25519-pubkey",
  "device_fingerprint": "sha256-of-install-id",
  "app_version": "1.4.0",
  "os": "win32-x64"
}
```
Response `200`:
```json
{
  "device_id": "uuid",
  "tenant_id": "uuid",
  "server_time": "ISO",
  "lease": { "...see §3..." },
  "entitlements": { "...see §4..." },
  "shop_bootstrap": { "tenant_name": "…", "branch": "…", "receipt_settings": {…}, "tax": {…}, "pos_mode": "retail" }
}
```
Errors: `410` code consumed/expired, `404` unknown code, `403` `license_required` (no active paid plan OR no paid desktop license purchase — **desktop is never free or trialed**, see D1), `403` tenant suspended, `409` `max_devices` entitlement exceeded.

**D1 (revised):** Activation requires a **paid desktop entitlement** — either (a) `tenants.plan_start_date` set (a started paid subscription), or (b) a `desktop_license_purchases` row with `status = 'paid'` for the tenant. Pending/trial tenants and unpaid purchases **cannot activate**. Purchased licenses are **perpetual** (once-off **$150**, `DESKTOP_LICENSE_PRICE_USD`) — a paid purchase keeps a device renewing indefinitely, unlike a lapsed subscription which stops renewals at `grace_until`. `max_devices` = plan seats + paid purchases (they stack).

Atomicity: code consumption + device row + lease issuance happen in one DB transaction. A retried activation with the same code returns `410`.

### 2.2b License purchases (tenant admin, JWT)

Desktop licenses are sold **once-off at $150** — no subscription required for desktop-only users.

**`POST /v1/licenses/purchase`** — creates a `pending` purchase + activation code.
Request: `{ "device_label": "…", "payment_ref": "optional gateway/invoice ref" }`.
Response `201`: `{ "purchase": { id, amount, currency, status }, "code": "TGA-…", "expires_at": "ISO" }`.
- `amount` is always server-set (`DESKTOP_LICENSE_PRICE_USD = 150`) — the client never sets price.
- The code activates only after the purchase is `paid` — `pending` codes return `license_required`. Settlement paths:
  - **Paynow** — `initiatePaynowCheckout` (existing `paynow-initiate` fn) → `PATCH /v1/licenses/purchases/{id}` with `payment_ref` = session reference → the `settle_desktop_purchase` trigger on `payment_sessions` flips the purchase when the session settles (callback, poll-status, or manual approval — all covered).
  - **Stripe** — `POST /v1/licenses/purchases/{id}/stripe-checkout` → hosted session tagged `metadata.kind='desktop_license'` + `purchase_id` → `stripe-webhook` marks it paid (idempotent).
  - **Manual** — `PATCH /v1/admin/licenses/purchases/{id}` (super admin) for cash/EFT settlements.
- One purchase = one activation code = one device seat.

**`GET /v1/licenses`** — the tenant's own purchases + issued codes (hint only — full codes are shown once at issue).

**`GET /v1/admin/licenses`** (super admin) — the unified issue feed: every activation code + purchase across all tenants, tagged `source: 'self' | 'staff'` — staff-issued licenses appear in the same list as customer purchases.

**`PATCH /v1/admin/licenses/purchases/{id}`** (super admin) — `{ "status": "paid" | "refunded" }`. Marking `paid` sets `paid_at` and unlocks the linked activation code. Staff-issued licenses (`source: 'staff'`) are created already `paid` with `amount: 0`.

### 2.3 Check-in / lease renewal (desktop, device-signed)

**`POST /v1/checkin`** — device authenticates with `X-Device-*` headers.
Request: `{ "checkin_id": "uuid", "app_version": "1.4.0", "os": "win32-x64", "offline_since": "ISO|null", "device_fingerprint": "sha256-hex" }`
- `device_fingerprint` is the stable machine fingerprint computed at activation; if the reported value differs from the stored one → `device_cloned` event + flag (license files copied to another machine).
Response `200`:
```json
{
  "server_time": "ISO",
  "device_status": "active|revoked",
  "lease": { "...new lease if renewed, omitted otherwise..." },
  "entitlements": { "..." },
  "flags": { "revoked": false, "messages": [] }
}
```
- `checkin_id` is a client-generated UUID deduped server-side (safe retry).
- **Rolling session token.** Each response carries `session_token` (opaque, rotated). The client stores it and presents it as `session_token` on the next check-in. The server accepts the current or previous token (one lost-response window); a mismatch marks the device `device_cloned` — only one physical copy of a cloned license can ever hold the latest token, so the second copy always diverges. First check-in after activation sends none.
- Server issues a **new lease** when ≥50% of the current lease has elapsed, or entitlements changed, or device was flagged for re-issue. Otherwise omits `lease` (client keeps its valid one).
- `flags.plan_inactive: true` → the tenant's paid plan lapsed (or never started). No new lease is issued; the device shows a persistent "subscription lapsed" state and stops selling at `grace_until` of its current lease.
- `device_status: "revoked"` → client must show license-revoked state and stop opening for business after a local shutdown grace (see §5).
- Failures: `401` bad signature/device unknown — client retries with backoff; must never block the POS while lease is valid.
### 2.3b Usage reports (desktop, device-signed)

**`POST /v1/report`** — flush of the license manager's local report queue (see §5b).
Request: `{ "reports": [{ "report_id": "uuid", "kind": "sale|inventory|session|error|lease_check", "occurred_at": "ISO", "data": { } }] }` — up to 500 entries per call.
Response `200`: `{ "accepted": n, "duplicates": m, "server_time": "ISO" }`.
- Reports are **append-only telemetry**, batched by the client and deduped by `report_id` (safe retry of a partially-acknowledged flush).
- A valid but revoked/suspended device's reports are still stored — a pirated install reporting in is evidence, not an error.
- Reports never carry credentials, card data, or line-item detail — aggregate counts and event kinds only.

### 2.4 Revocation

**`POST /v1/devices/{device_id}/revoke`** (tenant admin, JWT)
**`POST /v1/devices/{device_id}/unrevoke`** (tenant admin, JWT) — allowed while device is still reachable; reinstates on next check-in.
**`POST /v1/deactivate`** (desktop, device-signed) — self-deregistration during uninstall/transfer; frees the seat.

**`GET /v1/devices`** (tenant admin, JWT) — list: name, fingerprint, version, last_checkin, status, lease expiry.

Revocation takes effect **only at next check-in**. A device that never returns keeps its lease until expiry/grace — this is documented to customers as a licensing floor, not a bug.

### 2.5 Updates (desktop, device-signed)

**`GET /v1/releases/latest?channel=stable&version=1.4.0&os=win32-x64`**
Response when update exists `200`:
```json
{
  "manifest": {
    "version": "1.5.0",
    "channel": "stable",
    "min_supported_version": "1.2.0",
    "rollout_pct": 25,
    "release_notes_url": "https://…",
    "published_at": "ISO",
    "artifacts": [{
      "os": "win32-x64",
      "url": "https://…/TengaPOS-Setup-1.5.0.exe",
      "sha256": "…",
      "size_bytes": 81234567,
      "signature": "base64-ed25519-of-sha256-digest"
    }]
  },
  "manifest_signature": "base64-ed25519-over-canonical-manifest",
  "server_time": "ISO"
}
```
Up-to-date: `{ "update_available": false, "server_time": "ISO" }`.
Force-update: if `current_version < min_supported_version`, response adds `"mandatory": true`.

Rollout bucket: `sha256(device_id || version) mod 100 < rollout_pct`. Deterministic per device per version — staging is pure server config.

### 2.6 Installer download (public, unauthenticated)

**`GET /v1/download?os=win32-x64&channel=stable`**
Response `302` redirect → short-lived signed URL to the installer artifact in storage, or `404` if no published release for that channel/os. Anyone may download the installer — it is inert until activated (§2.2). Optional `GET /v1/download/info` returns JSON `{ version, size_bytes, sha256, url }` for the download page instead of a redirect.

### 2.7 Release management (Super Admin, JWT + `is_super_admin()`)

- **`POST /v1/releases`** — register `{ version, channel, min_supported_version, rollout_pct, release_notes_url, artifacts[] }`. Artifacts carry server-computed sha256 + signature (signed with the license key at publish time by an internal `sign-release` step, or pre-signed offline and verified before insert).
- **`PATCH /v1/releases/{id}`** — adjust `rollout_pct`, promote `beta→stable`, set `min_supported_version`, or `withdraw: true`.
- **`GET /v1/releases`** — list releases with artifact + rollout state.

### 2.9 Platform administration (Super Admin, JWT + `is_super_admin()`)

License lifecycle beyond tenant self-service — the Super Admin portal can act on any tenant's fleet.

- **`POST /v1/admin/licenses`** — issue an activation code for ANY tenant (`{ tenant_id, device_label, ttl_minutes? }`). Staff-issued codes may live longer than 15 min (max 7 days) for remote delivery by phone/WhatsApp.
- **`GET /v1/admin/devices`** — full fleet across tenants: device, tenant name, version, OS, **last_ip**, last check-in, lease expiry, status, security flags.
- **`GET /v1/admin/devices/{id}`** — detail + recent check-ins (with IP history) + security events.
- **`POST /v1/admin/devices/{id}/suspend`** — device stops receiving renewals at next check-in (flag `suspended`); reversible via `unrevoke`.
- **`POST /v1/admin/devices/{id}/revoke`** / **`/delete`** — revoke as before; `delete` marks `deleted` (terminal + license record retired, history kept in events).
- **`GET /v1/admin/events`** — security feed: failed activations, signature failures, cloned installs, unauthorized builds, suspicious IPs. Filter `?type=&device_id=`.
- **`GET /v1/admin/stats`** — fleet aggregates: devices by status, by app_version, downloads per release/channel, open infringement cases.
- **`GET /v1/admin/downloads`** — download log (IP, UA, OS, channel, release version).
- **`GET|POST /v1/admin/infringements`**, **`PATCH /v1/admin/infringements/{id}`** — crack/piracy case file (see below).

#### Cracked-install detection (what the server can actually see)

A modified build that **never contacts the API is invisible** — this must be stated plainly. Detection works at every network touchpoint, plus manual reports:

| Signal | Meaning |
|---|---|
| `activation_failed` | Bad/expired/reused code attempt — logs IP + submitted code hash |
| `signature_fail` | Request signed with a key that isn't the device's — forged device identity |
| `device_cloned` | Check-in where reported `device_fingerprint` ≠ activation fingerprint — license files copied to another machine |
| `unauthorized_build` | `app_version` that exists in no published release — patched/self-built binary phoning home |
| `update_probe_denied` | `/releases/latest` hit with invalid device auth — likely cracked binary looking for updates |
| `manual_report` | Super Admin logs a crack found in the wild (torrent, reseller, shared license file) |

Events set `flags` on the device row (`crack_suspected`, `cloned`, `unauthorized_build`) which the portal surfaces. Auto-revocation is **off by default** (false-positive risk) — a flag puts the device in the review queue; the admin revokes deliberately.

#### Infringement cases + usage billing

`desktop_infringement_cases` records each crack: source (server-detected vs manual), subject (device/tenant/IP/fingerprint), observed window, `plan_rate` (what they should have paid), `months_observed` → `estimated_damages = plan_rate × months_observed` plus optional `seats`. Status workflow: `detected → notice_sent → settled | escalated | closed`. `notice_sent` records a demand letter was dispatched (recipient, date, channel) — a documented legal trail, not an email integration.

### 2.8 Meta

**`GET /v1/meta`** (public) — `{ "api_version": 1, "server_public_key": "…", "channels": ["stable","beta"], "lease_days": 30, "grace_days": 14, "server_time": "…" }` — lets the desktop bootstrap and lets us rotate keys in an emergency (new key version field `key_id`).

## 3. Lease format

```json
{
  "lease_version": 1,
  "lease_id": "uuid",
  "device_id": "uuid",
  "tenant_id": "uuid",
  "device_public_key_fingerprint": "sha256-prefix",
  "entitlements": { "see §4" },
  "issued_at": "ISO",
  "expires_at": "ISO",          // issued_at + 30 days
  "grace_until": "ISO",         // expires_at + 14 days
  "key_id": "v1",
  "signature": "base64-ed25519-over-canonical-lease-minus-signature-field"
}
```

- **Lease duration: 30 days**, renewed rolling at check-in. Long enough for real offline stretches, short enough that a revoked/stolen install dies in ≤6 weeks.
- **Grace: +14 days** past expiry — POS fully functional, persistent "license overdue — connect to internet" banner. After `grace_until`: app refuses to open for selling (read-only data access allowed — decision point D2).
- Lease verifies **fully offline** against the embedded server public key. No network, no secret on the client.
- Tamper defense: signature covers every field; modifying `expires_at` invalidates it. Clock-rollback mitigated via `max_server_time_seen` (§1).

## 4. Entitlements

Derived server-side from the tenant's existing `plan_type`/`features` — no new source of truth:

```json
{
  "plan": "pro_package",
  "max_devices": 3,
  "modules": ["core_pos", "inventory", "reports"],
  "features": { "offline_sales": true, "receipt_printing": true, "local_users": true },
  "plan_expires_at": "ISO|null"
}
```

Embedded inside every lease — changing plan mid-term takes effect at next check-in. `max_devices` enforced at `/activate` (409 on overflow).

## 5. Offline & failure semantics

| Condition | Behavior |
|---|---|
| No network, lease valid | Full operation. Zero blocking calls. |
| Check-in fails (any reason) | Silent retry w/ exponential backoff (1h → 6h cap). Never blocks sales. |
| Lease expired, within grace | Full operation + overdue banner. |
| Past `grace_until` | App refuses new sales; read-only access to local data. Login allowed for viewing. |
| Device revoked | Takes effect at next successful check-in only. Then same as past-grace, plus "license revoked" message. |
| Clock rolled back | `expires_at` judged against `max(last_checkin_server_time, system_time)` — rollback can't extend a lease. |
| Update check fails | Logged, retried later. Never touches a running sale. |

**Business-data sync is explicitly out of this contract.** Licensing, updates, and sync are three separate systems; sync may reuse device auth but must never be required for sales.

## 5b. The License Manager (normative client rules)

The desktop ships a separate, always-present **License Manager** component — the file `license.dat` (or its platform equivalent) plus the background service that owns it. These rules are normative for the external desktop build:

- **Required to run.** If the license-manager file is missing, unreadable, tampered, or fails signature verification, the app **refuses to start** — no sale screen, no data access. This is distinct from an expired lease: tampering is fatal immediately; an untampered expired lease follows §5.
- **Persistent report queue.** The manager keeps an append-only local queue of usage events (sessions, sales counts, lease checks, errors — aggregates only, never credentials or line items). It needs **no network to keep reporting**: entries accumulate offline and flush via `POST /v1/report` the moment any connectivity appears. The queue survives reboots and app updates.
- **Offline vs. blocked — the hard distinction the app must make:**
  - *No route to the network at all* (adapter down, cable out, captive portal, DNS unreachable, connection timeout) → ordinary offline mode. Queue silently, full POS operation while the lease is valid.
  - *Active refusal* — TCP connection refused or reset by a middlebox, or a destination-specific block while general internet works (probe a control endpoint such as the API's own `/v1/meta` plus an unrelated host; if the internet is reachable but our API refuses/resets) → **the app treats this as the license manager being firewalled.** It shows a blocking screen: "TengaPOS License Manager is being blocked — allow `desktop-license` (and `license-manager` if split) through the firewall to continue," and does not open for business until the block clears. A deliberately-blocked license channel is not "offline" — it's a tamper signal.
- Reports from a revoked/pirated install are still accepted server-side — evidence collection, not an error.
- **Anti-tamper posture.** Client rules alone can't stop a patched binary — raise the cost instead:
  - **Entangled checks.** Verify the license in multiple code paths — startup, POS open, sale commit, receipt print, report export — not one gate. A single `if` to patch is a single point of failure.
  - **Watchdog handshake.** The License Manager runs as a separate process; the app handshakes with it on startup and periodically via a local challenge (random nonce → signed reply). No handshake → the app refuses. Deleting or neutering the manager file/process is then visible immediately.
  - **Verify the server, not just reachability.** The blocked-probe must confirm the responder is *our* server — present the pinned license public key + require a signed response — not merely "the port answers." A localhost shim answering 200 must not count.
  - **Redundant license copies.** Mirror license state in `license.dat` + the local SQLite. A missing/mismatched copy at any check is a tamper signal, even when the other copy reads fine.
  - **Sign the binary.** Authenticode-sign the installer and executables so a modified build fails Windows' own publisher check.
  - **Rolling token** (§2.3) — two machines sharing one copied license diverge on the session-token chain; whichever checks in second is flagged `device_cloned`.
  - **Dark devices.** A terminal that activated but has been silent (no check-in, no report) beyond the window the fleet UI shows is presumptive-pirated-or-abandoned — an admin follow-up trigger, not an automatic action.

## 6. Provisioning after activation

On `/activate` success the desktop:

1. Stores device keypair (OS-backed) + lease + entitlements.
2. Runs embedded first-run migrations → local SQLite DB.
3. Applies `shop_bootstrap` (tenant name, branch, tax, receipt settings, pos_mode).
4. Presents **local user setup** — create owner + PIN/password locally (bcrypt/argon2 in SQLite). No server user accounts involved.
5. Lands on POS. Sales, inventory, receipts all local; network only for license/update checks.

## 7. Desktop client responsibilities (normative)

- Ed25519 device keygen at first launch; private key in `safeStorage`/OS keystore, never in localStorage/plain config.
- Verify every lease + manifest + artifact signature with the embedded public key. **Any signature/hash failure → abort, never install, never accept.**
- Update flow: background check → download to staging dir → verify sha256 → verify signature → install via standard updater handoff → relaunch. Keep previous version's DB backup before migration.
- Store `max_server_time_seen`; on startup, effective-now = `max(system_time, max_server_time_seen)`.
- A failed license check must produce zero UI impact while a lease is valid — silent by design.

## 8. Server schema (new tables)

`desktop_activation_codes` — id, tenant_id, code_hash, label, status, expires_at, consumed_at, consumed_by_device_id
`desktop_devices` — id, tenant_id, name, public_key, fingerprint, status `active|revoked`, app_version, os, last_checkin_at, revoked_at/reason
`desktop_leases` — id, device_id, payload jsonb, issued_at, expires_at, grace_until, key_id (audit/history)
`desktop_checkins` — checkin_id uuid pk (dedupe), device_id, app_version, created_at
`desktop_releases` — id, version, channel, min_supported_version, rollout_pct, release_notes_url, published_at, withdrawn_at, manifest_signature
`desktop_release_artifacts` — release_id, os, url, sha256, size_bytes, signature
`desktop_usage_reports` — report_id uuid pk (dedupe), device_id, kind, occurred_at, data jsonb, received_at, ip
`desktop_license_purchases` — id, tenant_id, code_id, amount, currency, status `pending|paid|refunded`, source `self|staff`, payment_ref, paid_at (§2.2b)
`desktop_license_events` — id, type, device_id, tenant_id, detail jsonb, ip (security feed, §2.9)
`desktop_downloads` — id, release_id, version, os, channel, ip, ua
`desktop_infringement_cases` — id, source, status, device/tenant/ip/fingerprint subject, plan_rate, months_observed, seats, estimated_damages (generated), notice trail

RLS: tenant rows → own tenant's codes/devices (`users.tenant_id` match); releases → `is_super_admin()` for writes, device-signed for reads. Devices write only via the edge function (service role) — no direct table access. Usage reports + license events + downloads + infringement cases → staff/super-admin read only.

## 9. Error envelope

`{ "error": { "code": "string_snake_case", "message": "human readable", "retryable": true } }`
Codes: `code_expired|code_consumed|code_unknown|device_unauthorized|device_revoked|device_limit_reached|tenant_inactive|license_required|manifest_unsigned|version_unsupported`.

## 11. Release checklist

1. Build desktop installer (electron-builder) on CI.
2. Compute sha256 + sign digest with license private key (secrets manager, never in repo/CI logs).
3. Upload artifact to storage; register release via `POST /v1/releases` (channel `beta`, rollout `5%`).
4. **Staging verify:** clean VM → activate → confirm lease, offline sales, check-in renewal.
